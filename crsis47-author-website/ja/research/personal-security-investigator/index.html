証拠・時間・捜査官の判断

CRSIS-47
Personal Security Investigatorv0.2

次の証拠が届いたときに評価がどのように変化するかを検証するための、管理された環境。

実験的な実現可能性プロトタイプであり、検証済みまたは実用化された侵入検知システムではありません。

目的方法論チェックポイント評価トレーサビリティ制限事項

01 / 研究課題

評価を見直してください。
論理的な根拠を維持する。

Personal Security Investigator v0.2は、段階的な証拠開示を検証するためのローカルブラウザベースのテストハーネスです。架空のシナリオ、スケジュールされた証拠パッケージ、およびセキュリティ評価が時間とともにどのように進展するかを調査者が記録する方法を提供します。

その目的は、そのプロセスの実現可能性と使いやすさを検証することである。具体的には、情報が適格となる条件、調査官が下す結論、結論が変わる理由、そして入手可能な証拠が保存された各評価にどのように紐づけられるか、といった点を検証する。

本レビュー対象バージョンは、デバイスのスキャン、アカウントへの接続、独立したセキュリティ判定の生成は行いません。評価は人間のオペレーターによって入力されます。研究結果、検出性能の推定値、有効性に関する主張はここでは報告されていません。

02 / 実験方法論

提案されたワークフロー。
境界が限定されたプロトタイプ。

想定される実現可能性検証ワークフローは、6つの証拠公開が予定された固定の架空シナリオを使用します。これはプロトタイプの説明と提案された研究アプローチであり、検証済みの実験が完了したことを示すものではありません。

  1. 実行内容を定義する。 開始する前に、シナリオ、バージョン、調査担当者の役割、クロックモード、および記録手順を特定してください。
  2. T+0を確立する。 最初の証拠パッケージの公開から始めます。T+0は、侵入開始時刻、事件開始時刻、または評価が保存された時刻ではありません。
  3. 証拠は段階的に公開する。 現在のシナリオチェックポイントで確認可能な資料のみを確認してください。想定されるインターフェースは、制御されたステップスルーとリアルタイムスケジューリングを提供します。v0.2のクロックモード配線は、開発上の課題となっています。
  4. 記録し、再評価する。 分類と根拠を保存し、不確実性や代替説明を明記する。新たな証拠が得られ次第、判断を見直す。
  5. 記録を保存してください。 実行履歴とチェックポイント履歴をエクスポートして、非公開で確認できるようにします。研究結果を裏付けるために記録を使用する前に、スコアリング、タイミングルール、および検証手順を定義してください。
03 / 段階的な証拠開示予定されているリリースは6件です。

証拠時計。

シナリオ時間

荷物が審査対象となる時期を決定します。

壁掛け時計の時間

実際の実行経過時間を計測します。シナリオ時間や一時停止時間とは区別する必要があります。

チェックポイントで時間を節約

調査員が評価を保存した日時を記録します。これは、予定された公開後に発生する場合があります。

ステップ実行は、47秒の実時間検出結果ではありません。ブラウザのスケジューリング、バックグラウンドタブのスロットリング、および未解決のクロック動作により、タイミングの解釈が制限されます。

04 / 調査員の評価

結論。
そして、その説明。

MALICIOUS
捜査官は、公開された証拠が悪意のある解釈を裏付けるものだと判断した。
BENIGN
捜査官は、公開された証拠が正当な解釈を裏付けるものだと判断した。
UNCERTAIN
入手可能な証拠は、十分に明確な解釈を正当化するものではない。

これらは調査員が入力した分類であり、自動検出や検証済みの正解データではありません。また、このインターフェースでは、オプションで侵入確率と信頼度に関する主観的な推定値を入力することも可能になります。これらは別々の項目であり、いずれも較正済みとはみなされません。

根拠の説明が必要である。説明は、評価を公開された証拠と結びつけ、観察と推論を​​区別し、未解決の疑問点を特定し、代替的な説明を検討する必要がある。評価の変更は、以前の記録と照らし合わせて理解できるものでなければならない。

05 / トレーサビリティと監査記録

入手可能なもの。
結論はこうだった。

このプロトタイプは、保存された評価を、リリースされた証拠パッケージの識別子とリリースログのスナップショットに関連付けます。記録には、分類、根拠、オプションの確率と信頼度、シナリオ時間、保存タイムスタンプ、および実時間が含まれます。リリース記録では、予定されたリリース時間と記録されたリリース時間が区別され、一時停止と再開のアクションは別のログに記録されます。

このインターフェースでは、実行結果のJSONファイルとチェックポイントのCSVファイルへのエクスポートが可能です。以降のリリースでは、通常のインターフェースを通して以前の評価データが書き換えられることはありません。これはメモリ上の履歴であり、改ざん防止機能や独立したセキュリティを備えた監査台帳ではありません。ページを更新したり閉じたりすると、実行中の状態が失われる可能性があるため、保存するには明示的なエクスポートが必要です。

研究プロトコル、バージョン履歴、方法論、検証計画、実験記録などの非公開研究文書は、ウェブサイトとは別に保管されています。動作プロトタイプ、シナリオペイロード、および生の研究記録は、ここではホストされておらず、ダウンロードも提供されていません。

06 / 制限事項と開発状況

まずは実現可能性を検証する。
検証作業はこれからだ。

開発状況：実験段階 v0.2

  • 提供されるパッケージには架空のシナリオが1つ含まれています。そのため、悪意のあるケースと良性のケースの両方における性能を検証することはできません。
  • 評価は人間が入力する。このプロトタイプは、情報源を独自に検証したり、侵害を検出したり、自律的な対応能力を実証したりする機能を持たない。
  • ソースコードの検査により、クロックモードの初期化が不完全であることが判明しました。セレクタが実行状態およびエクスポートされたプロトコルメタデータに一貫して引き継がれていません。一時停止時間の計測についても修正と検証が必要です。タイミング比較は現状では妥当ではありません。
  • 証拠の選別は、提示方法の一つです。今後のパッケージ内容はローカルクライアントソースにバンドルされるため、これは安全な証拠配信や匿名化された証拠配信ではありません。
  • ローカルエクスポートとインターフェース履歴は、それ自体では暗号化の完全性、永続的な保存、独立した検証、または再現性を保証するものではありません。
  • 独立した検証、校正、生産準備、または検出性能の向上は確立されていません。

計画された検証

次のステップは、クロックと記録の一貫性の問題を解決し、テストリリースの適格性とスナップショットの保存をテストし、レビュー可能なプロトコルとシナリオセットを確定し、スコアリングと除外事項を事前に宣言し、独立したレビューによる再現性を評価することです。これらのステップは計画された作業であり、完了した検証ではありません。
