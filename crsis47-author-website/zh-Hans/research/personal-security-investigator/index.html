01 / 研究问题

重新评估。
保留推理过程。

Personal Security Investigator 和 v0.2 是一款基于本地浏览器的测试工具，用于探索渐进式证据披露。它提供了一个虚构场景、定时发布的证据包，以及一种允许调查人员记录安全评估随时间推移发展过程的方法。

其目的是检验该过程的可行性和可用性：信息何时变得合格，调查人员得出什么结论，结论为何发生变化，以及如何将现有证据追溯到每个已保存的评估。

本次评测版本不会扫描设备、连接账户或生成独立的安全性判断。其评估结果由人工操作员输入。本文不报告任何研究结果、检测性能评估或功效声明。

02 / 实验方法

建议的工作流程。
有界原型。

预期的可行性工作流程采用固定的虚构场景，并计划发布六次证据。这是对原型和拟议研究方法的描述，并非证明已完成经过验证的实验。

  1. 定义运行。 开始之前，请确定场景、版本、调查员角色、时钟模式和记录程序。
  2. 建立 T+0。 首先，请提供第一份证据包。T+0 并非指涉嫌入侵的开始时间、案件立案时间或评估文件保存时间。
  3. 逐步公布证据。 仅审查当前场景检查点适用的材料。预期接口提供受控的单步执行和实时调度；v0.2 中的时钟模式布线仍是一个开发问题。
  4. 记录并重新评估。 保存分类和理由，并说明不确定性和其他可能的解释。随着更多证据的出现，重新审视这一判断。
  5. 保留记录。 导出运行和检查点历史记录以供内部审查。在使用记录支持研究结论之前，请定义评分、计时规则和验证程序。
03 / 逐步披露证据六部计划发行作品

证据时钟。

场景时间

确定包裹何时符合审核条件。

挂钟时间

衡量实际执行时间。它必须与场景时间和暂停时间区分开来。

检查点 - 节省时间

记录调查员保存评估报告的时间；这种情况可能发生在预定发布之后。

单步运行并非 47 秒的实际运行时间检测结果。浏览器调度、后台标签页限速以及未解析的时钟行为都会限制时间解读。

04 / 调查员评估

结论。
以及它的解释。

MALICIOUS
调查人员认为已公布的证据支持恶意解读。
BENIGN
调查人员判断已公布的证据是否支持合理的解释。
UNCERTAIN
现有证据不足以做出足够明确的解释。

这些分类由调查人员输入，并非自动检测或经核实的真实结果。该界面还允许选择性地输入主观入侵概率和置信度估计值。这些是不同的字段；两者都未经校准。

必须提供理由说明。理由说明应将评估结果与已公布的证据联系起来，区分观察结果和推断结果，指出尚未解决的问题，并考虑其他可能的解释。评估结果的变更应与之前的记录相符，并能被理解。

05 / 可追溯性和审计记录

有哪些可供选择。
结论是什么？

该原型系统将已保存的评估结果与已发布证据包的标识符以及发布日志的快照关联起来。记录包括分类、理由、可选的概率和置信度、场景时间、保存时间戳以及实际经过时间。发布记录区分计划发布时间和已记录发布时间；暂停和恢复操作分别记录在单独的日志中。

该界面提供运行 JSON 和检查点 CSV 导出功能。后续版本不会通过常规界面覆盖之前的评估结果。这是一个内存历史记录，并非防篡改或独立安全的审计账本。刷新或关闭页面可能会丢失实时状态，因此需要显式导出才能保存。

私人研究文档（包括方案、版本历史记录、方法、验证计划和实验记录）与网站分开保存。工作原型、场景有效载荷和原始研究记录均不在此处托管或提供下载。

06 / 局限性和发展现状

可行性第一。
验证工作仍有待完成。

研发状态：实验性 v0.2

  • 提供的软件包仅包含一个虚构场景，无法证明其在典型的恶意和良性情况下均能保持性能。
  • 评估结果由人工输入。该原型系统无法独立验证信息来源、检测安全漏洞或展示自主响应能力。
  • 源代码检查发现时钟模式初始化不完整：选择器未始终如一地进入运行状态并导出协议元数据。暂停时间统计也需要修正和验证。目前，计时比较尚不合理。
  • 证据门控是一种呈现机制。后续的软件包内容会捆绑在本地客户端源代码中，因此这并非安全或匿名的证据交付方式。
  • 本地导出和接口历史记录本身并不能建立加密完整性、持久存储、独立审查或可重现性。
  • 目前尚未证实其通过独立验证、具备已校准的概率或达到生产使用条件，也未证明其检测性能有所提升。

计划验证

下一步工作包括解决时钟和记录一致性问题、测试发布资格和快照保存、确定可审查的方案和场景集、预先声明评分和排除标准，以及通过独立审查评估可重复性。这些步骤属于计划工作，并非已完成的验证。
